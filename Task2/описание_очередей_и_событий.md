# Очереди:
## События от клиента:

Региональная очередь для клиентских событий: BookingCreated, BookingCanceled,
Client->Api Gateway->booking queue->[booking srv]


## События от водителей:

Региональная очередь для водителей: DriverBookingAccepted, DriverUpdatedLocation
driver->Api Gateway->drvier queue->[driver srv, pricing srv]
(пускай будет в одной очереди, хотя их можно развести ибо частотной и TTL у них
совершенно разная)

## внутрисистемные события booking'а

очередь по созданию заказов, валидации заказов (fraud)


Жизненный цикл заказа(booking):

1) получения заказа от клиента (**BookingCreated**);
2) сервис "booking srv" вычитывает соотв. очередь и  регистрирует заказны в системе, клиент получает инф-ию, что заказ получен и обрабатывается ( на этом этапе возможно следует использовать batching);
3) заказ проверяется на мошенический, т.е. данные пропускаются через  сервис "fraud srv" и сервис аналитики(analytics srv);
4) если все впорядке, то публикуется событие **BookingAccepted**, которое дальше идет в  "pricing srv" для динамического ценобразования и возвращается в "booking srv" для изменения статуса заказа; если возникли проблемы, то формируется событие **BookingReject**;
5) по результатам динамического ценообразования генерируется событие **BookingPriceEstablished**  и отправляется в сервис "driver srv" для поиска водителей и "notification srv" для нотификации клиентов о цене возможной поездки;
6) при получении события **BookingPriceEstablished**  "driver srv" ищет наиболее подходящего водителя; если водитель нашелся (получено событие **DriverBookingAccepted**), соотв. сообщение отправляется в "payments srv" для резервирования необходимой суммы; то генерируется собите **BookingConfirmed**;
7) если никаких проблем с резервацией средств не возникло, то публикуется сообщение  **BookingConfirmed** для сервиса"booking srv", который менят статус заказ на "выполняется", синхронно уточняет у "geogaphy srv" время и маршрут прибытия такси, после чего генерируется соотв. push-сообщение через "notification srv";
