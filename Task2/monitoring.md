## Для мониторинга предлагается использовать классическую связку Prometheus+Grafana для визуализации и алертинга, для сбора логов ELK стек

Данные инструменты хорошо себя зарекомендовали в микросервисных архитектурах и считаются классическим выбором для соотв. задач.

## Бизнес-метрики для мониторинга

1) Общее кол-во заказов(счетчик заказов) за сутки\неделю и т.п.;
2) Кол-во выполненных заказов (возможна разбивка по регионам);
3) Кол-во выполняющихся заказов (возможна разбивка по регионам);
4) Кол-во отмененных заказов (возможна разбивка по регионам )
5) Географическое распределение заказов(разбивка по геообластям);
6) Кол-во задетектированных мошенических действий на платформе;
7) Кол-во работающих водителей (возможна разбивка по регионам);
8) Кол-во водителей, выполняющих заказ (возможна разбивка по регионам);
9) Прибыль за счет комиссии от платежей клиентов за день (возможна разбивка по регионам)

## Инфраструктурные метрики

1) Кол-во сообщений в очередях (нужно  для масштабирования);
2) Кол-во обращений по каждому из сервисов;
3) Кол-во сбоев по каждому из сервисов, возможно разбивка по методам (500-е vs 400-е);
4) Время обработки запроса целиком (p99);
5) Время обработки отдельных подзапросов для каждого сервиса -- разбивка времени обработки по сервисам; т.е. если запрос целиком обработан за 300мс, то сколько каждый сервис занял в этой обработке, можно, например, в % измерять от общего времени;
6) Метрики по каждой сервисной и тенантной бд -- кол-во запросов, утилизация пулов и т.п.
7) Кол-во входящего и исходящего трафика;
8) Метрики шлюзов по кол-ву соединений и их времени жизни.
